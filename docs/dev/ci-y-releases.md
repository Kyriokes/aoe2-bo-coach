- **Git:** una rama por fase (`fase-N-<nombre>`) con commits chicos. Cada fase sale de la anterior (ramas apiladas). El push a `main` (fast-forward) funciona cuando el usuario lo pide explícitamente en el chat; por iniciativa propia lo bloquea el clasificador de permisos. No hay `gh` ni conector de GitHub autenticado.
- **Repo público con licencia MIT.** CI con GitHub Actions en `windows-latest` (build + test de toda la solución) en cada push a cualquier rama. Como el repo es público, el estado del CI se consulta sin autenticación: `curl -s "https://api.github.com/repos/Kyriokes/aoe2-bo-coach/actions/runs?per_page=3"`. Los logs piden iniciar sesión, pero cada test que falla queda como anotación del job (paso "Tests fallidos como anotaciones"): `curl -s ".../actions/runs/<run>/jobs"` da el id del job y `curl -s ".../check-runs/<job>/annotations"` el mensaje. El 2026-10-20 un test falló una vez en el CI y pasó en la corrida siguiente con el mismo código (no se supo cuál; antes de las anotaciones). Las acciones están fijadas por SHA y el job de la web en `ubuntu-24.04`.
- main está al día con `fase-9-refinamiento` hasta la v0.9.86 (último push el 2026-11-03, con la app en castellano e inglés; cada push a main lo pide el usuario explícitamente). Para comprobar sin escribir nada que una migración está aplicada: llamar por `/rest/v1/rpc/<función>` con la clave publishable y una identidad con formato inválido (si existe, contesta el error de su validación; si no, `PGRST202`); la falta de "Perhaps you meant" en un `PGRST202` no prueba que no exista, y un bucket privado le da "not found" a un anónimo aunque exista.
- Versión portable: `dotnet publish src/BoCoach.App -c Release -r win-x64` da un `BoCoach.exe` autocontenido (166 MB, .NET adentro) + `data/` + `LEEME.txt`; en `.zip` pesa 62 MB. Probada desde otra carpeta: editor, overlay y coach en vivo con OCR. Sin compresión a propósito: comprimido, la RAM privada subía a 108-140 MB (descomprime los ensamblados en memoria); sin comprimir, 49-70 MB y 1,6 % de CPU.
- El CI deja la versión portable como artefacto (14 días). `release.yml` arma la release sola en cada push a `main` cuya `<Version>` no tiene etiqueta (desde el 2026-10-26: la descarga de la web estaba en la v0.9.33 con `main` en la v0.9.39 porque la etiqueta se subía a mano), o al subir una etiqueta `v*` a mano. Publicar sigue siendo decisión del usuario: es pedir el push a `main`.
